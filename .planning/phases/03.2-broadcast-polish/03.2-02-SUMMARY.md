## Decisions Made

- **fadeTabIn replaces wipeIn:** The JS adds both `active` and `wipe-in` to panels on switch. Because `.panel.wipe-in` comes after `.panel.active` in the cascade, the `wipe-in` animation property wins. Adding `fadeTabIn` only to `.panel.active` would have no effect. Fixed by updating `.panel.wipe-in` to also reference `fadeTabIn` — later rule wins, desired animation fires. Documented as Rule 1 auto-fix.

- **D-10 already implemented:** Roster card slide-down (`transition:max-height .45s cubic-bezier(.22,1,.36,1)` on `.pdet`) was already present at line 279. No work needed; noted in summary.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Updated .panel.wipe-in to use fadeTabIn instead of wipeIn**
- **Found during:** Task 1 (Tab transitions)
- **Issue:** The plan adds `fadeTabIn` to `.panel.active`, but JS always adds both `active` and `wipe-in` classes simultaneously. The `.panel.wipe-in{animation:wipeIn}` rule comes later in the cascade and would override `.panel.active{animation:fadeTabIn}`, meaning the new fade would never fire.
- **Fix:** Set `.panel.wipe-in{animation:fadeTabIn 0.2s cubic-bezier(.16,1,.3,1) both}` — both rules now reference fadeTabIn, and the later rule wins as expected.
- **Files modified:** index.html
- **Verification:** `grep "wipe-in" index.html` shows `fadeTabIn`, `wipeIn` keyframe preserved for backward compat
- **Committed in:** ad353e3 (Task 1 commit)
