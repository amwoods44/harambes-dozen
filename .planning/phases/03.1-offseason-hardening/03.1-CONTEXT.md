# Phase 3.1: Offseason Hardening - Context

**Gathered:** 2026-04-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Make every tab handle a zero-game offseason gracefully. The app currently shows NaN, Infinity, empty states, and misleading narratives when the current season has zero games played. This phase eliminates all offseason rendering failures so the app makes a strong first impression when shared with leaguemates. No new features — only guards, fallbacks, and defaults.

Key insight: This is NOT about building an "offseason mode" feature. It's about making every existing render function degrade gracefully when `D.matchup_weeks` is empty, `CUR_STANDINGS` has all-zero records, and current-season data doesn't exist yet.

</domain>

<decisions>
## Implementation Decisions

### Offseason Detection
- **D-01:** Add a global `IS_OFFSEASON` flag computed once in `buildCurrentSeasonData()`: `const IS_OFFSEASON = !D.matchup_weeks || Object.keys(D.matchup_weeks).length === 0;` Store on `D.isOffseason`. Every render function can check this cheaply.
- **D-02:** "Last completed season" means the most recent entry in `SEASON_YEARS` that has matchup data. In current state: 2025 is the last completed season. Compute once as `D.lastSeason` or `LAST_COMPLETED_SEASON`.

### NaN/Infinity Elimination (OFF-01)
- **D-03:** Every formula that divides by games played, total points, or win count must guard: `if(!totalGames) return 0;` or `if(!fpts) return '--';`. This affects: `renderPower()` composite score, `renderScoring()` heat map cells, `renderAnalytics()` Pythagorean wins, `renderPulse()` composite score, and the H2H Compare tool.
- **D-04:** When a value would be NaN, display `'--'` (double dash) not 0. Zero implies "measured and found zero." Dash implies "not yet measured." Use `'--'` consistently across all tabs.

### Historical Fallback (OFF-02, OFF-03)
- **D-05:** Tabs that show current-season game data should detect offseason and render last-completed-season data instead, with a clear label: "2025 Season" or "Showing 2025 — no 2026 games yet." Affected: Power Rankings, Scoring heat map, Analytics (H2H, All-Play, Pythagorean, SOS), Matchups.
- **D-06:** Draft tab: when current-season draft data is empty, show last season's draft by default. Year selector should still work.
- **D-07:** Moves tab: when current-season moves are empty, show last season's transactions by default.
- **D-08:** Rivals tab: compute rivalry records from ALL historical matchups, not just current season. Rivalry data should never be empty if historical seasons exist.

### Trade Defaults (OFF-04)
- **D-09:** Trades tab should default to "ALL" years when current season has zero trades. The year filter should pre-select "ALL" instead of the current year.

### Records Week Fix (OFF-05)
- **D-10:** `D.records` entries (biggest_blowout, closest_game, highest_score, lowest_score) have `week: null`. The `buildStats()` or record-computing function must capture the week number when finding each record. Trace the computation to find where week is dropped.

### Narrative Fallback (OFF-06)
- **D-11:** Awards tab: when current season has all-zero stats, show "2025 Season" awards (last completed season). Don't award superlatives from zero data.
- **D-12:** GM Dashboard overview cards: show all-time/career stats (lifetime wins, total points across seasons, career titles) not just current-season-only stats.
- **D-13:** Chronicle tab: suppress event generation from zero-value data. "All-Time High: 0 pts ?" should never render. Only generate chronicle events where the underlying stat is nonzero.

### Stat Strip (OFF-07)
- **D-14:** Hero stat strip should show offseason-appropriate values: "Most Points" → last season's leader, "Avg PF" → last season's average, "Rookies Drafted" → last draft class count. "Total Trades" already shows all-time (61) which is correct.

### Loading Screen Cleanup (OFF-08)
- **D-15:** After `loading-screen` fades out via CSS animation, set `display:none` on the element. Currently it has `fade-out` class but `offsetHeight > 0` — it's invisible but still in the DOM taking space.

### Claude's Discretion
- Exact wording for offseason labels ("2025 Season" vs "Last Season" vs "Showing 2025")
- Whether to add a small offseason banner at the top of the page or per-tab
- The threshold for "offseason" — is it strictly zero games, or also applicable during week 1 before all matchups are scored?
- Order of fallback: try current season data first, then last-completed, then all-time

</decisions>

<code_context>
## Existing Code Insights

### Root Cause Map (from audit)
- **Power Rankings NaN**: `renderPower()` composite score divides by totalGames/totalPts which are 0
- **Scoring NaN/Infinity**: Heat map cell calculation divides by games per week count (0)
- **Analytics NaN**: Pythagorean wins formula `wins_expected = pts_for^exp / (pts_for^exp + pts_against^exp)` — both are 0
- **Pulse NaN**: Reuses composite score calculation from Power
- **WkNaN**: `D.records.*.week` is null — `buildStats()` doesn't capture week number during record search
- **Draft empty**: `renderDraft()` only reads current-season draft picks
- **Moves empty**: `renderMoves()` only reads current-season transactions
- **Rivals empty**: `renderRivals()` only reads current-season matchups
- **Chronicle zero events**: Event templates render with 0 values instead of skipping
- **Loading screen**: `fade-out` CSS class on `.loading-screen` but no `display:none` after transition end

### Existing Guard Pattern
From Phase 1: render functions have guards like `if(!D.rosters)return;` at the top. Offseason guards follow the same pattern: `if(D.isOffseason){ /* show last-season fallback */ }`.

### Historical Data Access
- `D['matchup_weeks_'+year]` — per-season matchup data (from mergeHistoricalData, Plan 02-01)
- `D['weekly_scores_'+year]` — per-season weekly scores
- `D.unified_trades` — all trades across all seasons with `.yr` property
- `D.champions` — championship history array
- `D.franchise` — all-time franchise stats
- `SEASON_YEARS` — array of season year strings e.g. ['2023','2024','2025','2026']

### Key Lines to Modify
- `buildStats()` — wherever D.records is populated (find exact location)
- `renderPower()` — composite score formula
- `renderScoring()` — heat map cell rendering
- `renderAnalytics()` — Pythagorean wins, SOS, All-Play calculations
- `renderPulse()` — composite score
- `renderDraft()` — year selector default
- `renderMoves()` — data source selection
- `renderRivals()` — matchup data source
- `renderAwards()` — data source for superlatives
- `renderGM()` — stat card data sources
- `renderChronicle()` — event generation guards
- Hero stat strip builder — data source selection
- Loading screen — transition end handler

</code_context>

<specifics>
## Specific Ideas

- The `'--'` pattern for unmeasured values is already used in some places (e.g., `--PPG` in GM cards). Standardize it everywhere.
- War Room is the ideal offseason landing tab — it already has deadlines, exemption status, and draft capital. Consider making it the default tab when `D.isOffseason` is true.
- The offseason state should feel intentional, not broken. "2025 Season" labels should be confident, not apologetic.

</specifics>

<deferred>
## Deferred Ideas

- **Offseason Power Rankings**: Dynasty-specific power rankings based on roster value, contract health, draft capital, and age rather than win-loss record. This is a new feature, not a guard — belongs in Phase 4 or later.
- **League Lore offseason facts**: Anniversary-based facts ("1 year ago today, A.Woods traded..."). New narrative generation, not a fix — belongs in a future narrative phase.

</deferred>
