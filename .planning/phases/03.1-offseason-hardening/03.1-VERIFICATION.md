### Gaps Summary

Two gaps found, both related to the `null` week values that were intentionally set in Plan 01 as a fix for `'-'` producing WkNaN. The fix was correct and necessary — it eliminated the WkNaN root cause — but the downstream null-safety was only applied in `renderChronicle` (which is correct) and not in the other three call sites that display week values.

**Gap 1 — renderPulse NaN (OFF-01, OFF-02):** Line 5827 in `renderPulse()` computes a composite power score using `s25.fpts/maxP` where `maxP` can be 0 during offseason (all teams have 0 fpts). The identical fix was applied to `renderPower` line 3006 (`||1`) but was not replicated in the Pulse tab version of the same calculation. Additionally, renderPulse does not have a `D.isOffseason&&D.lastSeason` fallback var pattern like renderScoring/renderAnalytics/renderMatchups, so it always reads CUR_STANDINGS during offseason.

**Gap 2 — Null week display in ticker/Trophies/Pulse (OFF-05):** `buildTicker` (line 2965), `buildHeroHist` LEAGUE LORE facts (lines 2924-2925), `renderTrophies` records grid (lines 3300-3301), and `renderPulse` record cards (lines 5821, 5824) all concatenate `'Wk'+week` or `'Week '+week` without a null guard. Before `mergeHistoricalData` runs (which sets real integer week values via the all-historical `computeRecords` call at line 2309), these display `"Wknull"` or `"Week null"`. The Chronicle at lines 5905, 5907 correctly uses `(week?' • Wk '+week:'')` — that null-safe pattern needs to be replicated at the four remaining call sites.

Both gaps are 1-2 line fixes each. They do not affect data integrity or cause crashes — only user-visible string artifacts during offseason.
